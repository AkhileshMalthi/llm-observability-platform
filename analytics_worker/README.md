# Analytics Worker

The Analytics Worker is an asynchronous Python process responsible for capturing and processing logging events generated by the `proxy_service`. By running independently, it ensures that the fast response times of the proxy are not impacted by the latency of calculating analytical metrics or interacting with the database.

## Architecture & Data Flow

1. **Redis Pub/Sub:** The worker continuously listens to the `llm-logs` Redis channel.
2. **Processing:** Upon receiving a log payload (which includes original prompts and response contents), the worker:
   - Synchronously calculates the number of input tokens using `tiktoken`.
   - Counts output tokens.
   - Computes an estimated request cost based on configured pricing matrices.
3. **Database Sink:** Inserts the computed struct into a ClickHouse dataset (`llm_logs` table) alongside latency specs and trace IDs.

## Capabilities

- **Resilience:** If the database becomes unavailable, a worker process can implement simple retry patterns or a dead-letter queue.
- **Offloaded Computation:** Computes prompt parsing, metrics generation, and asynchronous insertions entirely separated from standard HTTP request fulfillment. 

## Development

The worker service is part of the `docker-compose.yml` and is managed directly through Docker for local testing. See the root `README.md` for startup commands.
